# 接続PCの名前と削除

Hubの「接続PC」で、永続端末IDごとに名前・利用停止・登録削除を管理します。名前の一致から別の端末を統合しません。名前が重複する旧登録には注意表示が付き、ID・観測IP・証明書指紋で識別して改名または削除できます。

## 名前の規則

参加申請、申請の許可、端末の改名、互換参加コードの利用で、Hubの同じ保存境界が一意性を検証します。名前は前後のUnicode空白を取り除き、Unicodeの小文字化後の文字列で比較します。ASCIIの大文字小文字や `É` / `é` は区別しません。Unicodeの正規化（NFC/NFKC）は適用しないため、結合文字と合成済み文字、全角と半角、互換文字は別名です。内部空白も保持します。空名・制御文字・UTF-8で256バイトを超える名前は保存できません。

有効な承認待ち、許可、停止、恒久失効の登録は名前を占有します。申請の期限切れと登録削除は名前を解放します。互換参加コードは名前を予約せず、使用時に再検証します。別操作との競合では、名前衝突または古いrevisionを理由に保存を拒否し、入力を保持します。申請側では別の名前を指定して再申請します。管理画面では入力欄の近くに理由を表示します。

旧データに重複があっても自動改名・統合・許可の付け替えは行いません。自分の現在名と比較上同じ名前の保存は、所属変更などを妨げないよう許容します。新しい別名への変更では一意性を検証します。

## 削除の操作と影響

一覧の「削除」は、表示名、端末ID、観測IP、登録時のIP、接続状態、証明書指紋を示す確認画面を開きます。「取消」またはEscapeでは何も変更しません。確認中に設定が変わると保存を拒否するため、最新情報から対象を確認し直します。名前だけで削除対象を決定しません。

旧MCP方式で受入済みかつ終了未確認のタスクが、対象端末を含む委任経路に残っている場合、削除は拒否します。オフライン、時間経過、Hubの再起動を完了とみなしません。Desktop側で停止・完了とその終端通知を確認してから再試行します。Hub上の「停止」は新規利用を止める可逆操作であり、実行済みタスクの停止完了を意味しません。

削除成功時は、旧端末の参加資格と更新資格を失効し、所属、当該IDを直接指定する方向付きルール、未使用の短期資格と現在の公開・生存情報を取り除きます。別端末のID・ルール、グループのルール、保存済みの仕事と履歴の帰属は保持します。未受入の認可は取消済みにし、新しい依頼や再委任を許しません。Desktopに保存された利用先の選択は元のIDのままですが、Hubの宛先一覧と認可から外れるため使用できず、新しい登録へ自動的に移されません。

削除は新規利用を失効させる操作です。すでにGatewayが受け付けたモデル通信は終端まで継続します。providerの生成や端末上のプロセスを停止した、あるいは完了したとは扱いません。削除後の新しいmodel permit claimは拒否します。

削除済みID・名前・削除時刻は一覧の「削除済みの登録」で確認できます。Hubで取得済みのMCP履歴は既存の保持上限（最大64件・30分）の範囲で表示・保存できますが、削除済み端末からの再取得はしません。Desktopの正本とログは削除しません。

共有プロジェクトの参加解除と端末登録削除は別操作です。共有の仕事・サービスの停止確認は[共有仕事の運用](shared-work.md)に従います。

## 再参加と保存互換性

同じ名前は新しい参加申請で再利用できます。旧資格は復活せず、新しい鍵による申請と管理者の許可、プロジェクトの操作・実行PC指定が必要です。実行PCは各プロジェクトの作業フォルダーを改めて登録します。端末の共通設定や証明書をコピーして旧IDを復活させる手順はありません。

端末台帳はschema 5です。schema 1〜4はCA、ID、ルール、保存済み認可を保って読み込み、読み取りだけではファイルを変更せず、次の保存時に5へ進めます。schema 4でnullableの `deleted_at_ms` を追加して削除済み登録を失効記録として保持し、schema 5でnullableの `windows_username` を追加しています。旧データのWindowsユーザー名を推測して補いません。通常登録128件、削除済み記録1024件に制限し、上限到達時に過去の失効記録を黙って捨てません。旧schemaへ戻す書き換えは行いません。
