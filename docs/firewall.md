# Hub PCの受信許可

WindowsのHub PCで、ローカル管理画面の「PCの接続 → このHub PCで受信許可を設定する」を使います。Hub管理者へのログインと、Windows管理者によるUAC確認は別です。ほかのPCからのWeb管理では、このPCのOS設定を変更できません。

1. 社内LAN側のHubとGatewayを開始します。
2. 許可する接続元PCのIPv4またはCIDRを1〜16件入力します。例は `192.168.10.21`、`192.168.10.0/24` です。DomainまたはPrivateのうち、実際に信頼するプロファイルを選びます。
3. 「変更内容と現在のルールを確認」で、現在の実行ファイル、Hub側IPv4、二つのTCPポート、接続元、プロファイル、既存ルールを確認します。
4. 確認チェックを入れ、「この内容でWindowsへ設定を依頼」を押します。Windows PowerShellの管理者確認に60秒以内に応答してください。取り消した場合や結果が不明な場合、成功とは表示せず、現在のルールを読み直して案内します。
5. 登録後は参加DesktopからHubへの接続を診断します。そのPCでHub AIを使う場合は、Desktopの「PCの接続 → 接続の詳細・診断 → このPCでHubのAIを使う場合の診断」でGatewayも確認します。

対象は現在の `moyai-hub.exe`、具体的な受信IPv4、稼働中のHub／Gatewayの受信TCPポートだけです。接続元とHubのIPv4はRFC1918（10/8、172.16/12、192.168/16）に限定します。Public、Any、全ネットワーク、IPv6、外向き通信、Web管理用ポート、OSのネットワークプロファイル変更は扱いません。別のアドレス体系や組織管理のポリシーが必要な環境は、「受信許可の設定を管理者へ依頼」から内容を渡してください。

登録はWindowsのローカル `PersistentStore` に一つのルールとして保存します。ルール名は実行ファイルとHub保存先で区別します。再度同じ内容を設定しても重複を作りません。変更する場合は既存内容と更新後の内容を確認します。名前・識別情報・実行ファイル・通信条件がこのHubの管理内容と一致しないルールは、自動で上書き・解除しません。会社のGPO、ほかのアプリのルール、手動変更されたルールはPC管理者へ確認してください。

「表示中の既存ルールを解除」も同じ確認とUACを経由します。設置先を移す場合やHubを削除する場合は、元のHubを開始した状態で解除します。配布用Setupのアンインストールはログオン開始登録を解除しますが、このFirewallルールは解除しません。元の設置先を既に削除した場合は、表示・記録したルール名と内容をPC管理者が確認してください。

設定確認中はネットワーク開始・停止を待ちます。実行ファイル、公開IP、ポート、接続元の範囲を変えた場合は再確認が必要です。Gatewayポートが0（自動選択）の既存環境では再開始時に実ポートが変わることがあります。チームの標準ポートは固定してください。

このルールの登録確認は、別PCからの到達成功や組織ポリシーによる有効化の保証ではありません。拒否ルール・GPO・社内ネットワーク機器は別途確認します。UAC拒否、途中失敗、応答不明時には操作を自動再実行しません。

実装はWindows標準の[NetSecurityルール](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule?view=windowsserver2025-ps)と、[Start-ProcessのRunAs](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1)を使います。利用時のダウンロードや追加モジュール導入は行いません。

開発検証では `tests/firewall-helper.test.ps1` の模擬NetSecurityで新規・同内容・更新・解除・外部変更・期限切れ・部分失敗を確認します。実Firewall書込み・実UAC・物理別PCの受入は、専用環境の検証結果と区別します。
