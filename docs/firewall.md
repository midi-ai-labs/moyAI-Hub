# Hub PCの受信許可

WindowsのHub PCで、ローカル管理画面の「PCの接続 → このHub PCで受信許可を設定する」を使います。管理画面はHub PCの起動操作から開きます。受信許可の変更時には、別途Windows管理者によるUAC確認が必要です。ほかのPCからのWeb管理では、このPCのOS設定を変更できません。

通常は配布パッケージのSetupで固定の場所へ導入し、更新も同じ導入先へ行います。展開フォルダーを毎回変えて直接起動すると、前の実行ファイルに対する受信許可は引き継がれません。`--launch`は保存済みのHub・Gatewayを開始した後（起動済みの再利用時も）、OSの現在のルールを照合します。未登録・不一致・競合・確認不能なら、認証済み管理画面の受信許可欄を開きます。一致している場合は追加操作もUACもありません。管理画面でも接続先が変わるとルールを読み直します。未登録、IP／ポート／現在のプロファイルとの不一致、手動変更を表示し、別の設置先を指すmoyAI管理ルールがある場合は配置の確認も案内します。ルールの読み取り失敗を「未登録」や「通信可能」とは扱いません。

1. 社内LAN側のHubとGatewayを開始します。
2. 未設定・不一致の場合は設定欄が開き、未入力なら現在のLAN（既存ルールがあればその範囲）から接続元とDomain／Privateの候補を入力し、変更内容を表示します。入力済みの内容は保持します。候補を入力・確認しただけではOS設定は変わりません。対象の範囲を確認し、必要なら接続元PCのIPv4またはCIDRを1〜16件へ変更してください。Publicや取得できないLANでは候補を作らず、手入力とPC管理者への確認を案内します。
3. 「変更内容と現在のルールを確認」で、現在の実行ファイル、Hub側IPv4、二つのTCPポート、接続元、プロファイル、既存ルールを確認します。
4. 確認チェックを入れ、「接続を許可して続ける」を押します。Windows PowerShellの管理者確認に60秒以内に応答してください。取り消した場合や結果が不明な場合、成功とは表示せず、現在のルールを読み直して案内します。
5. 受信許可を確認した後に「接続ファイルを保存」が使えます。配布した参加DesktopからHubへの接続を診断します。そのPCでHub AIを使う場合は、Desktopの「PCの接続 → 接続の詳細・診断 → このPCでHubのAIを使う場合の診断」でGatewayも確認します。

会社の管理者が別途ルールを設定している場合は、手順3の「受信許可を会社・PC管理者が設定している場合」を開き、現在のHubへの許可済みを確認すると配布できます。この確認は画面内だけの一時的な判断で、OS設定確認済みには変えません。画面を開き直すか接続先・確認結果が変わると解除します。HubとGatewayがともにloopbackの場合は受信許可を要求せず、同一PC専用の接続ファイルであることを表示します。

## 管理者へ設定スクリプトを渡す

確認チェックを入れ、「管理者に渡す設定スクリプトを保存 (.ps1)」で `Allow-moyAI-Hub.ps1` を保存できます。保存だけでは設定しません。管理者は内容を確認し、**Hub PCで**PowerShellから実行します。スクリプトは追加ソフトを必要としません。

```powershell
.\Allow-moyAI-Hub.ps1 -CheckOnly
```

`-CheckOnly` は設定を変更せず、対象PC・Hubの保存設定・実行ファイル・現在のルールを照合します。設定する場合は管理者としてPowerShellを開き、同じスクリプトを `-CheckOnly` なしで実行します。表示した許可範囲を確認し、`APPLY` と入力した場合だけ設定します。会社のスクリプト実行ポリシーで制限される場合は管理者の手順に従ってください。

管理者用スクリプトの出力には固定したGatewayポートが必要です。保存値が0（自動選択）の既存環境は、ポートを固定してHubの接続受付を再開してから出力してください。固定せずに現在のポートを許可する場合は、画面の「接続を許可して続ける」を使えます。

出力後にHubの配置・実行ファイル・接続設定・既存ルールが変わった場合は自動適用せず、新しいスクリプトの出力を求めます。終了後はHubの「受信許可を再確認」と、参加Desktopでの接続診断を行ってください。

## 設定する範囲と更新

対象は現在の `moyai-hub.exe`、具体的な受信IPv4、稼働中のHub／Gatewayの受信TCPポートだけです。接続元とHubのIPv4はRFC1918（10/8、172.16/12、192.168/16）に限定します。Public、Any、全ネットワーク、IPv6、外向き通信、Web管理用ポート、OSのネットワークプロファイル変更は扱いません。別のアドレス体系や組織管理のポリシーが必要な環境は、「受信許可の設定を管理者へ依頼」から内容を渡してください。

登録はWindowsのローカル `PersistentStore` に一つのルールとして保存します。ルール名は実行ファイルとHub保存先で区別します。再度同じ内容を設定しても重複を作りません。変更する場合は既存内容と更新後の内容を確認します。名前・識別情報・実行ファイル・通信条件がこのHubの管理内容と一致しないルールは、自動で上書き・解除しません。会社のGPO、ほかのアプリのルール、手動変更されたルールはPC管理者へ確認してください。

Windowsが返す接続元の `192.168.1.0/255.255.255.0` と `192.168.1.0/24`、アプリパッケージ指定なしの `null` と `Any` は同じ条件として照合します。この表記差だけでルールを書き換えたり、追加のUAC確認を求めたりしません。実際の範囲変更、不正なマスク、特定パッケージへの限定は同一と扱いません。

「表示中の既存ルールを解除」も同じ確認とUACを経由します。配布用Setupのアンインストールはログオン開始登録を解除しますが、このFirewallルールは解除しません。

更新で実行ファイルや既定保存先が変わった場合は、新版の「以前の配置の受信許可 → 以前の配置を確認」を使います。現在の保存先、または移行済みの旧既定保存先に対応するルールだけを表示します。実行ファイル・保存先・IP・ポート・接続元・プロファイルを確認し、チェックを入れて「選択した旧ルールを解除」を押してください。旧実行ファイルは不要で、Hub／Gatewayの接続受付が停止中でも使えます。手動変更されたルールは解除できません。別の独自保存先のルールも対象外です。PC管理者へルール名と内容を渡してください。

設定確認中はネットワーク開始・停止を待ちます。実行ファイル、公開IP、ポート、接続元の範囲を変えた場合は再確認が必要です。Gatewayポートが0（自動選択）の既存環境では再開始時に実ポートが変わることがあります。チームの標準ポートは固定してください。

このルールの登録確認は、別PCからの到達成功や組織ポリシーによる有効化の保証ではありません。拒否ルール・GPO・社内ネットワーク機器は別途確認します。UAC拒否、途中失敗、応答不明時には操作を自動再実行しません。

更新後も「受信許可を再確認」から現在の状態を確認できます。入力中の接続元・プロファイルを周期更新で書き換えません。別設置先のルールは自動移行・削除せず、そのルールの接続元範囲を新しい設置先へ自動転用しません。

実装はWindows標準の[NetSecurityルール](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule?view=windowsserver2025-ps)と、[Start-ProcessのRunAs](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1)を使います。利用時のダウンロードや追加モジュール導入は行いません。

開発検証では `tests/firewall-helper.test.ps1` の模擬NetSecurityで新規・同内容・更新・解除・外部変更・期限切れ・部分失敗を確認します。実Firewall書込み・実UAC・物理別PCの受入は、専用環境の検証結果と区別します。
