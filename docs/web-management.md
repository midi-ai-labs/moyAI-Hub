# ブラウザーからHubを管理する

2026-09-21。Rustサーバーと通常のWebブラウザーで管理します。Hub PCの起動操作、または管理を許可されたPCのDesktopから開きます。ID・パスワードを設定・入力する手順はありません。URLを知っているだけでは管理操作できません。

モデルの登録・編集・一覧確認、端末の承認・停止・削除、グループと方向付き利用許可、ネットワークの開始・停止、選択した端末のMCP履歴をブラウザーで操作します。保存処理はRustサーバーの同じ`Admin`が所有します。Desktop用の相互TLSと端末の利用許可は独立して維持します。

「PCの接続」は、接続先の設定・Hub開始、Windowsの受信許可、接続ファイルの配布、参加許可とDesktopからの接続診断を順に行います。Gatewayポートは保存済み設定を使います。初期表示では設定欄を折りたたみ、変更する場合だけ「モデル通信ポートを変更する（通常は変更不要）」を開いて開始前に別途保存します。最初のPCで使えることを確かめてから同じ接続ファイルを残りのPCへ配ります。「プロジェクト」では、プロジェクトと操作・実行PCを準備します。「管理画面のURL」は管理者がこの画面を開くためのURLです。一般利用者にはDesktop用の接続ファイルを渡し、管理用URLをPCの接続先として入力しません。

### ほかの操作と保存が重なった場合

「プロジェクト」の通常編集では入力を保持します。「入力を残して最新の設定と比較」で現在保存されている値との差を確認し、「比較した内容で編集を続ける」を押すと、保持した入力を修正・保存できます。比較や継続だけではサーバーへ保存しません。保存直前にも変更を照合するため、再び競合した場合はもう一度比較します。操作・実行PCを外すことになる差分も表示します。既存の利用者・groupの役割は通常のPC編集では変更しません。

削除された対象や選択PCは、入力を自動で別対象へ保存せず選び直します。削除・利用資格の変更・実行停止確認などは対象と確認内容を開き直してください。比較内容は編集中のブラウザーだけに保持し、この画面の利用終了や表示切替で破棄します。受付結果が不明な通信失敗は、同じ要求の受付確認を使います。

## このPCで使う

PowerShellなどからHubを起動します。

```powershell
.\moyai-hub.exe
```

新規保存先の管理URLは`http://127.0.0.1:9080/admin/`です。スタートメニューの「moyAI Team Management」、Hub単体配布の`Start-Hub.cmd`、または`moyai-hub.exe --launch`から開いてください。起動元のWindows利用環境を確認し、一度限りの起動情報でブラウザーの利用を許可します。直接URLだけを開いた未認証のブラウザーでは、起動方法を案内します。

起動ticketは60秒・一度限りで、URLのfragmentから専用cookieへ交換します。画面はticketを読み取ると直ちにアドレスから除きます。使用済み・期限切れ・通信結果が不明な場合は同じ方法で開き直してください。「この画面の利用を終了」はそのブラウザーの資格を失効させます。Hub・Gateway・既存仕事は停止しません。管理PCを失った場合も、Hub PCのWindows利用環境から管理画面を開き直してPCの対応・権限を修復できます。

保存済みWeb設定がある場合はその設定で自動開始します。ポートだけを変える場合は`--web-port 9082`のように指定します。`0`は空きポートの自動選択です。`--web-port`は他端末へのWeb公開をOFFにした設定として保存します。

`127.0.0.1`はブラウザーを開いたPC自身を指します。別端末からの管理には下記の公開設定を使います。

## 保存先・状態確認・終了

保存先は`--data-dir`、環境変数`MOYAI_HUB_DATA_DIR`、既定のアプリデータフォルダーの順で決まります。Windowsの既定値は従来版と同じ`%APPDATA%\ai.midi.moyai.hub`です。明示指定がなければ以前のcatalogや端末設定を引き継ぎます。同じ保存先でサーバーを重複起動することはできません。

```powershell
.\moyai-hub.exe --data-dir C:\moyai-hub-data
.\moyai-hub.exe --status --data-dir C:\moyai-hub-data
.\moyai-hub.exe --stop --data-dir C:\moyai-hub-data
```

`--status`は稼働中のHubのWeb URLと状態を表示します。`--stop`はその保存先のHubとGatewayを停止します。どちらも停止中のHubを自動起動しません。起動したコンソールで`Ctrl+C`を押しても終了します。

ブラウザーやタブを閉じてもHub・ネットワーク・Gatewayは動き続けます。ブラウザーの「接続の受付を停止」は端末通信とGatewayを止め、Web管理画面を維持します。Hubサーバー本体を終了するとWebを含む待受も停止します。

サーバーを再起動するとWebは保存済み設定で自動開始します。通常のコンソール起動では端末ネットワークと従来のモデルサーバーは停止状態なので、必要な通信をブラウザーから開始してください。Windowsでは、このPCのローカル管理画面にある「サインイン時の自動起動」から任意登録できます。現在のWindowsユーザーのHKCU Runへ、表示した実行ファイル・保存先と `--launch --no-browser` を登録します。別PCの管理画面からは変更できません。同梱の `Setup-moyAI -Uninstall` は配布manifest・実行ファイルのhashと起動先・コマンドが一致するRunner／Hubの登録を解除し、profileを保持するため、事前の手動解除は不要です。Hub単体の削除や任意の設置先移動では、事前に元のローカル管理画面で解除してください。独自変更した開始登録は自動解除の対象外なので、変更を行った方法で解除してください。Windowsサービス・ログオン前やサインアウト後の無人稼働は対象外です。

### ワンクリックでホスティングする

実行ファイルと同じフォルダーへ `scripts/Start-Hub.cmd` と `scripts/Stop-Hub.cmd` を配置します。`Start-Hub.cmd`、または `moyai-hub.exe --launch` を指定したショートカットから、バックグラウンドのHub起動・保存済み端末ネットワークとGatewayの開始・通常の既定ブラウザー起動まで進みます。初回のネットワーク未設定時だけ、Web画面で具体的なIP・ポートを入力して開始します。ブラウザーを閉じてもホスティングは続き、同じ入口を再度開いてもプロセス・待受を重複させません。停止は `Stop-Hub.cmd` または `--stop` です。

成功した待受先と案内IPは `network-hosting.json`（`schema_version: 1`）へatomic保存します。Gatewayポートは既存の端末設定を使います。新規保存先の標準は9472、従来の0（自動選択）も維持します。保存データの破損、IP変更、ポート競合でネットワークを再開できない場合は、エラーを返してWebを維持します。画面から設定を修正し、開始成功時だけ保存を更新します。Web自体の開始失敗はHubを終了し、`hub-startup.log`へ記録します。ログは次回起動時に1 MiBを超えていれば前回分一つへ切り替えます。

`--launch --no-browser`は結果（PID・起動済み本体の再利用を示す`already_running`・Web URL・開始状態・初回設定の要否・ネットワークエラー）をJSONで返します。通常の起動では管理画面にも起動／再利用の案内を表示し、画面上部でHub本体の応答状態を確認できます。この表示はモデル接続や端末ネットワークの開始状態と独立しています。起動案内のURL fragmentは初回応答後に除去し、再読込では案内を繰り返しません。設定済みのネットワークを開始できない場合は終了コード1、初回未設定は0です。`--web-port` / `--web-settings`は未起動時のみ併用でき、起動済みサーバーのWeb設定を暗黙に変えません。保存先の選択順序は通常起動と同じです。

## 他のPCから使う

他端末向けWeb公開は初回OFFです。公開する場合はJSONファイルを用意し、起動時に`--web-settings`で指定します。`--web-port`と同時には指定できません。どの方式でも、このPC専用のloopback HTTPを併設します。

```powershell
.\moyai-hub.exe --data-dir C:\moyai-hub-data --web-settings C:\moyai-hub-data\web-settings.json
```

| `remote.mode` | 公開方法 | 準備するもの |
| --- | --- | --- |
| `off` | このPC専用 | `local_port`のみ |
| `http` | 接続先案内のみ。管理画面の利用・管理操作は不可 | 待受先と公開HTTP Origin |
| `https` | HubがHTTPSを受け付ける | 待受先、公開HTTPS Origin、Web用証明書と秘密鍵 |
| `proxy` | 同じPCのreverse proxy経由 | 固定loopback待受とproxyの公開HTTPS Origin |

別PCから管理するには、Hubの詳細設定でそのPCを管理権限のある利用者へ結び付け、HTTPSの管理URLを設定します。管理権限はその利用者を引き継ぐ全PCが対象です。そのPCのDesktopで「Hubの管理画面を開く」を押すと、相互TLSで現在のPC登録・利用者の対応・管理権限を確認して一度限りの起動ticketを渡します。PCの停止・失効・対応先変更後に以前の管理資格を使い続けられません。LANの平文HTTPは管理操作不可です。

遠隔の管理画面ではプロジェクト・PCの許可と保存設定を管理できます。モデル接続先の探索・変更、Hubの待受設定やWindows変更など、Hub PC上の実行・通信を伴う管理操作はHub PCから直接開いた画面で行ってください。詳しい許可対象は現在の管理command境界が決めます。Windowsの受信許可は[Hub／Gatewayの限定受信許可](firewall.md)を確認し、UACを経て設定します。

### 既存のLAN HTTP公開設定

設定自体は読み取れますが、このURLでは管理操作を行えません。別PCのDesktopから開くには下記のHTTPS設定を使います。Hub PCではスタートメニューまたはCLIから開いてください。

```json
{
  "local_port": 9080,
  "remote": {
    "mode": "http",
    "bind": "0.0.0.0:9081",
    "public_origin": "http://192.168.10.2:9081"
  }
}
```

この例の別端末向けURLは`http://192.168.10.2:9081/admin/`です。HTTPでは証明書は使いません。ブラウザーでクリップボード操作が利用できない場合は設定ファイルのダウンロードを使います。

公開Originはscheme・host・portだけを指定し、`/admin/`などのpath、ユーザー情報、query、fragmentを含めません。ブラウザーは設定した公開OriginのURLでアクセスします。別名や別のHostへ自動で信頼範囲を広げません。

### Hub自身でHTTPSを受け付ける

```json
{
  "local_port": 9080,
  "remote": {
    "mode": "https",
    "bind": "0.0.0.0:9081",
    "public_origin": "https://hub.example.com:9081",
    "certificate_path": "C:/certs/hub-fullchain.pem",
    "private_key_path": "C:/certs/hub-key.pem"
  }
}
```

証明書と秘密鍵はHubを起動するアカウントが読み取れる絶対パスで指定します。各PEMファイルの上限は1 MiBです。開始時に秘密鍵との組合せ、leaf証明書の有効期間、公開Originの名前・IPとSANの一致を確認します。証明書の信頼はアクセス元ブラウザーで判定します。

Web証明書の発行・信頼配布・更新は運用側が担当します。Desktopへ配布するHub CAや端末用証明書を、Webの利用者認証や証明書例外として流用しません。証明書・設定を変更する場合はHubを停止してから新しい設定で再起動してください。

### 同じPCのreverse proxyを使う

```json
{
  "local_port": 9080,
  "remote": {
    "mode": "proxy",
    "bind": "127.0.0.1:9081",
    "public_origin": "https://hub.example.com"
  }
}
```

proxyはHubと同じPCで動かします。proxy用待受は固定の`127.0.0.1:ポート`で、このPC専用Webの待受とは別です。proxyは公開Originと一致するHost、元のOrigin、CSRFヘッダー、`/admin/`のpathを保持して転送します。証明書やproxy自体の設定・起動は既存の運用側で行います。

Hubは`Forwarded`や`X-Forwarded-*`から公開先や権限を推測しません。private制御用`/host/*` APIをproxyの転送先にしません。

## 操作・保存と通信の境界

保存時は入力開始時のrevisionを検証し、別の画面が先に保存した場合は最新状態での再確認を案内します。周期更新は入力・選択・折りたたみを保持します。変更の結果を確認できない場合は自動再送しません。

共通設定は `hub-config.moyai-join`（内容は従来と同じ公開TOML）、MCP履歴はMarkdownとしてブラウザーのダウンロード先へ保存します。共通設定は各Desktopで同じファイルを取り込み、端末ごとのIDや秘密鍵は含めません。標準セットアップ済みのPCでは専用拡張子をダブルクリックしてPCの接続先確認へ進めます。従来の `.toml` の手動読込みも維持します。履歴は管理画面で明示的に取得した時点のスナップショットです。全件を常時収集するものではなく、保存元は各Desktopです。

Web設定はdata directoryの`web-management.json`（schema 1）へ、開始成功後にatomic保存します。CLIへ渡すJSONは`local_port`と`remote`の設定本体であり、保存用の`schema`・`settings`ラッパーは付けません。設定ファイルの上限は32 KiBです。証明書のパスを保持しますが、秘密鍵本文をWeb設定へ保存しません。

設定の破損・未知schema、ポート競合、証明書の不備などでWebを開始できなければ、公開CLIの起動は失敗して終了します。元の設定は上書きしません。正しい`--web-settings`か`--web-port`を明示して再起動し、待受と保存が成功したときに設定を更新します。

WebはHost・Origin照合、CSRF、要求サイズ・同時処理数・処理期限の上限を適用します。`/admin/session`はCSRF値と現在の認証状態を返し、`POST /admin/access`で起動ticketをHttpOnly・SameSite=Strictの用途別cookieへ交換します。HTTPSではSecure属性を付けます。管理要求はcookieと一致するsession識別子も必要です。別タブのsessionが変わった場合、古い画面の管理操作は拒否します。CSRF値そのものや公開URLは管理資格ではありません。

静的画面はビルド時に組み込みます。ブラウザー操作は許可された`Admin::dispatch`へ送られ、端末の相互TLS APIやprivate `/host/*`制御とは入口を分けます。private制御は同じPCのCLIから、利用者限定ファイルに保存した資格で接続します。
